# warband-metal

A Metal renderer for Mount & Blade: Warband on macOS. The Steam version of the game draws with OpenGL, which Apple deprecated years ago. This project loads a library into the game when it starts that takes over its drawing and does it with Metal instead. The game's files are not modified, and the game still runs as an Intel program under Rosetta 2.

In a 200 vs 200 custom battle on a MacBook Pro M5:

| | OpenGL (1512x982, limited to 120 fps) | Metal (3024x1964, unlimited) |
|---|---|---|
| Average | 110 fps | 199 fps |
| Median second | 117 fps | 210 fps |
| Slowest 10% of seconds | 86 fps or less | 131 fps or less |
| Slowest second | 55 fps | 109 fps |

Metal also draws at the display's native resolution, four times the pixels of the OpenGL path. The runs were played by hand, one each, so read the result as "roughly twice as fast"; details are in `docs/baseline.md`.

## Using it

You do not need to compile anything. A ready-made app is on the Releases page.

1. Download `warband-metal-<version>.zip` from the Releases page. Safari unzips it for you; otherwise double-click the zip. You get `Warband Metal.app`.
2. Allow the app to run. macOS blocks apps that were downloaded and are not signed by a registered Apple developer, and this one is not, so the first double-click only shows a warning. Do one of the following, once:

   **With Terminal** (the route that is known to work). Open Terminal, paste this and press Return:

       xattr -dr com.apple.quarantine ~/Downloads/"Warband Metal.app"

   If the app is not in Downloads, type `xattr -dr com.apple.quarantine ` with a space at the end, drag the app onto the Terminal window, and press Return. The command removes the "downloaded from the internet" mark from the app; it changes nothing else.

   **Without Terminal.** Double-click the app and close the warning. Open System Settings → Privacy & Security, scroll down to Security, and click "Open Anyway" next to the message about Warband Metal. Confirm with your password or Touch ID, then open the app again. This route has not been verified; if the game still does not start afterwards, use the Terminal command.

3. Double-click `Warband Metal.app`. A window opens with the renderer's options, grouped and explained, four ready-made settings ("Everything on", "Everything but hair", "Faster", "As the game looks"), the module to play, and a Play button, which starts the game on Metal. The game's own settings, the ones its launcher offers, are in the same window: resolution, starting in a window, vertical sync, frame-rate limit, texture and shadow detail under Video at the top, and language, blood, cheats, version check, edit mode (the game's scene editor and free camera, Ctrl+E in a scene) and sound at the end. They are read from the game's `rgl_config.txt` and `language.txt` when the window opens, written back when Play is pressed, and left alone by the four settings. The game's anti-aliasing is not among them: under Metal, Multisampling takes its place. The choices are remembered; a checkbox makes the app start the game at once from then on (hold Option while opening it to get the window back). If the game is not in the default Steam library, it asks for the "MountBlade Warband" folder once and remembers it.

You can keep the app anywhere, for example in Applications.

Each option in the window is one of the `WBM_*` variables listed below, and a variable set in the environment the app is started from wins over the window. The window offers what works with the game as it is: the app changes none of the game's files and needs no changed ones. What needs texture packs or models made with the tools below (horses' coat, fur layers, mane and tail strands, glTF materials) is left out of it, and so are trials; they can still be switched on with their variables. The tools themselves (`texture_tool`, `gltf_export`, `gltf_import`, the frame player and model previewer) are not in the download; they are built from source. The choices are kept in `~/Library/Application Support/warband-metal/settings.plist`.

The game's in-game options (Options in its menu) still work as before; what is changed there shows in the window the next time it opens.

If something looks wrong, the log of the latest run is in `~/Library/Logs/warband-metal/trace.log`.

**Do not use this in multiplayer.** It loads code into the game process, which is the kind of thing anti-cheat systems object to.

Tested on one machine: MacBook Pro M5, macOS 26.5, game version 1.174 from Steam, Native module (menus, world map, towns, battles). Other modules, Intel Macs and older macOS versions are untested.

## Status

The Metal renderer draws the whole game and passes Metal's API validation (`MTL_DEBUG_LAYER=1`) in a 200 vs 200 battle and on the world map. The rest of this document is for developers.

## Tried and set aside

- **MetalFX frame interpolation** (issue #10). The idea was to make a frame between each two of the game's and show both. On the test machine it lowered the frame rate everywhere. In a 200 vs 200 battle capped at 60 fps, it gave 40 in light scenes and about 15 in the fight, against 60 throughout without it. There are two causes. The interpolator costs about 10 ms of GPU time a frame at 3024×1964 on an M5. And showing two drawables per game frame left the game waiting for the screen, with VSync on or off. It is worth another look only together with a presenting thread of its own, and only for a game that runs at about 40–70 fps by itself (with heavier effects on, or on slower Macs), or if MetalFX's interpolator becomes cheaper. The code is on the branch `feature/frame-interpolation`, and the measurements are in the issue.

## Build

Needs the Xcode Command Line Tools, git and python3. The game does not have to be installed to build, only to run.

    make

The first build downloads its dependencies at pinned versions into `third_party/` and compiles the two shader libraries, glslang and SPIRV-Cross (`scripts/build_deps.sh`); cmake is not needed. It also fetches the headers of GLEW 2.1.0 and SDL 2.0.8, the versions the game bundles; `stubs/*.tbd` stand in for those two libraries at link time.

This produces `build/libwbmetal.dylib` for x86_64 (the game runs under Rosetta 2). `make app` builds `build/Warband Metal.app` and `make dist` zips it.

Releases are built by GitHub Actions (`.github/workflows/build.yml`): pushing a tag that starts with `v` publishes the zip on the Releases page. The steps are in `docs/releasing.md`.

Every feature is behind a `WBM_*` variable and off unless it is set, so work goes into `master` as soon as it builds, is off by default and leaves the picture as it was with its variable unset (compare replays of a captured frame, `scripts/replay.sh`, with the build before). A release is the launcher's list of options (`launcher/launcher.m`), which is what makes a feature visible to players, and a tag.

Static analysis (needs `brew install llvm cppcheck` and `pipx install lizard`): `make analyze` runs the Clang Static Analyzer, `make lint` clang-tidy with the checks in `.clang-tidy`, `make cppcheck` cppcheck over the plain C++ files, and `make metrics` lists functions longer than 150 lines or with more than 30 paths through them. `scripts/check.sh <what> <file...>` checks only those files; `make compile_commands.json` writes `build/compile_commands.json` for clang-tidy and editors.

## Run

    scripts/run.sh

This starts the game on Metal with the library just built. `WBM_MODE=trace scripts/run.sh` runs the game's own OpenGL renderer with every call traced, which is how the renderer was developed and is still the reference to compare against.

Each run writes to a new directory, `traces/<timestamp>/`, also reachable as `traces/latest`:

| File | Content |
|---|---|
| `trace.log` | Setup calls (shaders, textures, buffers, framebuffers, SDL) and any frames logged call by call |
| `summary.txt` | Call counts per function and thread, every distinct argument combination, framebuffer layouts, frame times. Rewritten every 300 frames and at exit |
| `shaders/` | The exact source of every shader passed to `glShaderSource` |
| `programs.txt` | Uniforms and attributes of every linked program, as reported by OpenGL |
| `fps.log` | One line per second: frame rate, average and worst frame time |
| `extensions.txt` | Extensions of the game's GL context |
| `frames/` | PNG of each frame that was logged call by call |

While the game runs, `scripts/snap.sh` logs the next frame call by call and saves it as a PNG. `scripts/snap.sh 10` waits ten seconds first, which leaves time to switch back to the game.

## Environment variables

| Variable | Meaning |
|---|---|
| `WBM_MODE` | `metal` (default): the Metal renderer. `trace`: OpenGL with tracing. `native`: the game's own OpenGL calls are left untouched and only frame times are recorded |
| `WBM_TRACE` | `1` traces the calls in Metal mode too, at a cost in frame rate. Off by default there |
| `WBM_VSYNC` | Overrides the swap interval. `0` asks for an uncapped frame rate |
| `WBM_SCALE` | Metal mode: resolution multiplier for the screen and screen-sized render targets. Defaults to the display's scale (2 on Retina); `1` renders at the game's own resolution, as OpenGL does |
| `WBM_MSAA` | Metal mode: samples per pixel for the screen and screen-sized render targets, `2` or `4`. Smooths geometry edges, and alpha-tested edges (foliage, hair, fur) through a rewrite of the shaders' alpha tests. Default `4`; `1` turns it off |
| `WBM_DYNAMIC_SHADOWS` | Metal mode: `1` draws a second shadow map every frame from the objects of the engine's depth pre-pass, so that characters, horses and gear cast shadows on everything and at any distance, and suppresses the engine's ground decals for them. Needs the game's "depth effects" option. The map has two parts: a wide one, `WBM_DYN_RANGE` metres to each side of a point ahead of the camera (default 60), and a fine one for sharp shadows of thin things close by, `WBM_DYN_NEAR` metres to each side (default 12, `0` for none). `WBM_DYN_BIAS` (metres, default 0.05) moves surfaces towards the sun before the comparison. `WBM_DYN_FOLIAGE` (metres, for example 30; 0, the default, for no limit): cut-out things without bones (leaves, bushes, fences) farther off than this are left to the engine's own coarser map, since in a forest they are most of what this map draws. Grass, which the pre-pass leaves out, is taken from the main pass a frame late. Uses about 260 MB of video memory. Off by default |
| `WBM_REVERSE_Z` | Metal mode: `0` uses the conventional depth mapping. By default depth is reversed (far is 0), which spreads the float depth buffer's precision evenly and avoids flicker between distant, nearly coplanar surfaces |
| `WBM_CONTACT_SHADOWS` | Metal mode: `1` adds short screen-space shadows towards the sun, for contact detail the shadow map is too coarse for. Computed with ambient occlusion and subject to the same limits. `WBM_CONTACT_STRENGTH` (default 0.5) and `WBM_CONTACT_LENGTH` (metres, default 0.4) tune it. Off by default |
| `WBM_SKY_AMBIENT` | Metal mode: `1` gives the ambient light a direction. What the engine adds as flat ambient and sky light is tinted by the colour of the scene's sky on the side a surface faces, and surfaces facing sideways or down receive sunlight bounced off the ground, less of it where the ground about them lies in the shadow of scenery (under a gate, beside a tower), as the engine's shadow map has it. `WBM_SKY_AMBIENT_STRENGTH` (0 to 1, default 0.6) sets the tint, `WBM_BOUNCE` (default 0.5) the bounce. Outdoor scenes only. Off by default |
| `WBM_TORCH_SHADOWS` | Metal mode: a strength, for example `0.8`: the engine's point lights (torches, candles, fires; up to four in a scene) cast shadows, which in the game they do not. Each frame the scene is drawn from every such light into a cube of depths, and the game's shaders look their surface up in it, so anything casts, on screen or off. Needs the game's depth effects, like `WBM_DYNAMIC_SHADOWS`. Also gives the shaders the lights in their proper order: the game tells them only which is nearest, and they then take the scene's first light for all the others. `WBM_TORCH_MAP`: the width of a cube's face in texels (default 1024). `WBM_TORCH_SELF` (metres, default 0.5): scenery this near a light casts no shadow from it, so that a torch's own bracket, which the light sits in, does not darken the wall behind it; `0` lets everything cast. Off by default |
| `WBM_TORCH_LIGHTING` | Metal mode, with `WBM_TORCH_SHADOWS`: `1` works the point lights out at every pixel where the game's standard shaders (people, gear, furniture) do it at the vertices: with the normal map where there is one, and with a highlight per light of the kind `WBM_PBR` gives the sun's, in place of the engine's. Off by default |
| `WBM_ROOM_PROBE` | Metal mode: `1` gives interiors surroundings of their own. Indoors (where the engine gives the sun no colour) the sky is no longer what metal reflects or what tints the ambient light (`WBM_PBR=3`, `WBM_SKY_AMBIENT`): a small picture of the room in every direction from the camera takes its place, filled in from the finished frames themselves as the camera looks round, a fifth at a time; what has not been looked at yet starts as the nearest edge of the first frame. It has no depth, and trails a little behind sudden changes of light. `WBM_ROOM_PROBE_EVERY` (default 1) updates it only every so many frames. Off by default |
| `WBM_TEXTURES` | Metal mode: folders of replacement textures, separated by colons, the first one winning. A file named after one of the game's texture files (`helmets_new_a.png` or `.dds` for the game's `helmets_new_a.dds`; PNG, JPEG, TIFF, BMP and DDS in DXT1/3/5 or 32-bit are read) is loaded in place of the game's texture, at whatever size it has, when the game uploads it. Subfolders are searched too. Without the variable, `~/Library/Application Support/warband-metal/textures` is used if it exists. The game's files are not touched. Applies to frame captures played back as well, where `WBM_GAME` names the game's folder if Steam did not put it in the usual place |
| (texture packs, continued) | A pack may also hold `<name>_pbr.png` for the game's texture `<name>`: metalness in red, roughness in green, and in alpha how much of the light from all round reaches each spot (ambient occlusion), laid out like the texture. With `WBM_MATERIALS=1` such a map replaces the renderer's own estimates for that texture; in shaders without a highlight of their own (most of what buildings are drawn with) its occlusion dims the ambient light and its roughness gives the sun a highlight where the surface is smooth enough to have one. And `<name>_depth.png`: the surface's heights, white the highest, which `WBM_PARALLAX` then goes by instead of guessing them from the texture's brightness, on any material and not stone alone. `make build/texture_tool` builds a tool that writes these maps for the game's textures from their specular maps (`build/texture_tool pbr <folder>`), to be used as they are or corrected by hand, and that exports the game's textures as PNG for editing or enlarging (`build/texture_tool export <folder> [name...]`). Pictures that come back from that work are made into a pack with `build/texture_tool import <folder of pictures> <pack folder>`: a picture named after one of the game's textures replaces it; `<name>_basecolor` does the same, and `<name>_normal` replaces whatever normal map the game's materials put with that texture; `<name>_metallic` and `<name>_roughness` (grey), or `<name>_orm` (as glTF packs them), with `<name>_ao`, become `<name>_pbr.png`; `<name>_height` becomes `<name>_depth.png`; `<name>_opacity` goes into the texture's alpha; glTF's `<name>_anisotropy` (KHR_materials_anisotropy: direction in red and green, green up the picture, strength in blue) becomes the renderer's hair map `<name>_hair` with the long hair's colour beside it, and `<name>_sheen` (KHR_materials_sheen: colour, roughness in alpha) is kept as it is, both as PNG; normal maps are taken to have green pointing up the picture, as Blender has it, and are turned about for the game (`--normals directx` if they are the game's way already); a texture that lost its alpha on the way gets the game's own back; `--gain 2` darkens pictures that were made twice as bright as the game's to look right elsewhere; `--dds` writes the pack as `.dds` files in the game's own compression (DXT1, or DXT5 where alpha holds something) with their smaller sizes, which take a quarter to an eighth of the video memory of PNG and load without unpacking; alpha that is all or nothing (leaves, twigs, fences) has its edges softened by the enlargement's step, so that the alpha test cuts along smooth lines and not in the steps of the texels it was enlarged from (`--hard-alpha` keeps it as it is) |
| `WBM_WIND` | Metal mode: a strength, for example `1`: trees, bushes and grass sway, the more the higher up. Foliage is whatever is drawn with a texture whose file name says so (tree, bush, grass, plant, leaf and the like; bark and trunks stay still). Only the position on screen moves; shadows stay as they are. Off by default |
| `WBM_FOLIAGE` | Metal mode: how much sunlight comes through leaves, for example `0.6`: on the side turned from the sun where a shader lights by the surface's direction, and for the engine's own grass and leaf shaders, which do not, when looking towards the sun. Off by default |
| `WBM_UPSCALE` | Metal mode: a share of the screen's size each way, for example `0.67`: the scene is drawn that much smaller (0.67 is under half the pixels) and Apple's MetalFX enlarges the finished picture to the screen's size before the interface is drawn on it at full sharpness. Everything the scene costs per pixel gets cheaper: shading, shadows, ambient occlusion, fur. Fine detail is a little softer or crisper than drawn in full, depending on the picture. Needs macOS 13 and the game's own post effects on, as the other screen effects do; 0.5 to 0.8 is the useful range. Off by default |
| `WBM_UPSCALE_MODE` | Metal mode, with `WBM_UPSCALE`: `temporal` uses MetalFX's temporal scaler in place of the spatial one. The scene is drawn shifted by a different fraction of a pixel each frame, and MetalFX builds the picture from several frames, knowing from depth, from the camera's movement and from the things that move by themselves where each pixel was a frame ago. Much closer to the picture drawn in full than the spatial scaler, and it smooths edges itself, so `WBM_FXAA` is left out; costs a few milliseconds more. `WBM_UPSCALE=1` is then allowed too: nothing is enlarged, edges are smoothed over frames. What sways in the wind says how it moved through a second render target (`WBM_UPSCALE_SWAY=0`: it does not, and leaves smear); particles and water have no such record, so on macOS 14.4 and later a reactive mask tells the scaler to take them from the frame itself: blended draws that leave depth alone and whose vertices are filled afresh each frame (smoke, sparks, fire, glows) mark it by their alpha, or by alpha and brightness where they are added, and water by a fixed share (`WBM_REACTIVE_WATER`, default 0.5); `WBM_REACTIVE` is the most a pixel is marked (default 0.9; `0` for no mask), and `WBM_DEBUG_REACTIVE=1` shows the mask in red over the dimmed scene. Not with `WBM_MSAA` above 1. Sets `WBM_LOD_BIAS` to match unless that is given. `WBM_DEBUG_MOTION=1` shows the movements as a picture (grey: none). Off by default |
| `WBM_ALPHA_HASH` | Metal mode, without multisampling: `1` makes the edges of cut-out textures (leaves, grass, fences, hair, chain) dithered instead of hard: where a pixel is partly covered, it is kept or dropped against a pattern of noise, in the right proportion, and the depth pre-pass drops the same pixels. Meant for `WBM_UPSCALE_MODE=temporal`, which moves the pattern each frame and averages the frames, so that edges come out smooth and twigs and strands thinner than a pixel stay in view instead of breaking up. On its own it only trades stair steps for dots. Off by default |
| `WBM_SHARPEN` | Metal mode: 0 to 1, for example `0.3`: the scene is sharpened, each pixel pushed away from the average of its neighbours, less where they already differ much, never past the darkest or brightest of them. With `WBM_UPSCALE` it works on the enlarged picture, which MetalFX has sharpened somewhat already: there 0.2 to 0.3 is plenty. Off by default |
| `WBM_CONTRAST`, `WBM_SATURATION`, `WBM_WARMTH` | Metal mode: colour grading of the finished scene, each about -1 to 1 and 0 for no change: contrast is an S-curve about middle grey (negative flattens), saturation strengthens or weakens colours, warmth shifts towards red or blue without changing brightness. Applied in the engine's final shader after the tone map; needs the game's HDR mode. Off by default |
| `WBM_WATER` | Metal mode: `1` reworks the surface of the engine's water: it reflects the scene's own sky (with `WBM_PBR=3`) by how steeply it is seen, little straight down and nearly all along the surface; the bed shows through clearly at the edge and less with every metre of depth, the water's own blue-green taking over; two layers of ripples break up the repeating pattern; foam lies along the shore and round whatever stands in the water; and the sun glitters on the ripples. Depth and foam need the game's depth effects. With the depth effects it also looks into a copy of the scene taken just before the water is drawn: the bed is seen bent by the ripples, and the surface reflects what stands by it (banks, trees, people) wherever that is on screen, found by a search along the mirrored line of sight; elsewhere the sky stays. `WBM_WATER_REFLECTIONS=0` leaves that out; `WBM_WATER_STEPS` (default 24, 4 to 64) sets how far and finely the search goes, which is its cost on pixels that show water; `WBM_WATER_EVERY` (default 1) makes the copy only every so many frames. Off by default |
| `WBM_PARALLAX` | Metal mode: a depth in metres, for example `0.05`: stone and brick textures (recognised as for `WBM_MATERIALS`) on unskinned, normal-mapped surfaces are looked up where the line of sight meets a surface with depth, the texture's own brightness, well blurred, standing for height, so that stones stand out from their joints and shift a little as the eye moves. Fades out with distance. A mild effect; too large a value smears. Off by default |
| `WBM_BOUNCE_LIGHT` | Metal mode: a strength, for example `1`: lit surfaces throw some of their light, in their own colour, on what is near them (sunlit ground into the shade beside it, a bright cloak onto a wall), worked out from the picture itself at a quarter of its resolution (`WBM_BOUNCE_HALF=1`: at half, which is finer and costs more than twice as much): only what is on screen can give light. Computed with ambient occlusion and subject to the same limits. Off by default |
| `WBM_FUR` | Metal mode: a strength, for example `1`: a horse's coat is lit softly, with a velvety rim where it is seen edge-on, and the engine's hard streaks of highlight toned down. Applies where a texture pack's `<name>_pbr.png` says in its blue channel that the surface is coat, which `build/texture_tool pbr` works out for horses (not armour, cloth or saddle); without such a map nothing changes. With `WBM_DYNAMIC_SHADOWS=1` a little sunlight also comes through thin parts of the coat (ears) seen against the sun. `WBM_EYES=1` gives the game's plain horses a highlight in the eye as well. `WBM_FUR_SHELLS` (for example `10`; 0, the default, for none) draws the coat of horses near the camera again in that many layers, each a little farther out and holding only the hairs that reach it, which gives short fur with depth; `WBM_FUR_LENGTH` (metres, default 0.012) and `WBM_FUR_RANGE` (metres from the camera, default 9) set how long and how far, and `WBM_FUR_DENSITY` (hairs per metre, default 1400) how fine: it costs nothing, but finer than the screen can show turns to noise. Each layer is one more draw of the horse. A pack file `<name>_hair.png` refines all of this for a texture: red and green give the way the hair is combed (128 for none; red rightwards, green down the picture), blue what grows (255 long hair such as mane and tail, about 128 coat, 0 nothing). Long hair then gets twice as many layers of its own (`WBM_HAIR_LENGTH`, metres off the body, default 0.07): thicker strands that hang along the combing and downwards and swing a little; it shines in bands across its strands, reflects the sky, is darker inside than at its surface as the sun's angle has it, and with `WBM_DYNAMIC_SHADOWS=1` casts shadows, the fur leans the way it is combed and droops, and blue replaces the `_pbr` map's coat mask. `WBM_HAIR_STRANDS=1` (a trial) draws that long hair as strands instead of layers: locks rooted all over the marked skin, laid out by the vertex shader from the map's combing and hanging down, drawn with the horse's own shader and bones, so the model itself is not changed; the mane grows from the crest of the neck only and falls down its sides (`WBM_MANE_LENGTH`, metres, default 0.18), the tail's hair (what hangs on the skeleton's last two bones) runs on along the tail and past its end, long from the dock and shorter farther down (`WBM_TAIL_LENGTH`, default 0.8); mane and tail swing a little, stream out behind a horse that is moving, straight back at a gallop, and cast their own shadows with `WBM_DYNAMIC_SHADOWS=1`; and `WBM_HAIR_STRANDS_DENSITY` (strands to the square metre, default 30000, at most 12000 to a horse) sets how many. `build/texture_tool hair <picture> <name> <folder>` makes such a map from a picture of the texture with all but the long hair blacked out. Off by default |
| `WBM_FUR_ANISOTROPY`, `WBM_FUR_SHEEN` | Metal mode, with `WBM_FUR`: a horse whose texture has a hair map, a `_pbr` map and a sheen map from `texture_tool import` is lit as glTF's KHR_materials_anisotropy and KHR_materials_sheen light it, in place of the fur's own stand-ins: a microfacet highlight from the `_pbr` map's roughness and metalness, stretched along the hair by the hair map's direction (strength: its blue times `WBM_FUR_ANISOTROPY`, default 0.8, as glTF's anisotropyStrength), and a sheen in the sheen map's colour and roughness (times `WBM_FUR_SHEEN`, default 1). Both are reflected light, added on top of the base colour |
| `WBM_PEOPLE_HAIR` | Metal mode: `1` draws fine loose strands over the hair and beards of people near the camera. The game's hair mesh stays as the body of the hair; thousands of hair-thin ribbons are rooted all over it, run the way its texture is painted, lift a little off it and droop, and a few stray, so that the outline is no longer a polygon's. They sway with `WBM_WIND`. They are left behind a little when their owner moves off and settle when it stops, and with `WBM_DYNAMIC_SHADOWS=1` they cast shadows. The hair, mesh and strands alike, is also lit as the horses' manes are: a narrow white band off the strands, a wider one in the hair's colour, light through it when the sun is behind, and a sheen from the sky, in place of the engine's two streaks. Strands are shorter where the painted hair is short (beards, cropped heads). `WBM_PEOPLE_HAIR_RANGE` (metres from the camera, default 5), `WBM_PEOPLE_HAIR_LENGTH` (the longest strand, metres, default 0.06), `WBM_PEOPLE_HAIR_DENSITY` (strands to the square metre of mesh, default 60000, at most 6000 to a mesh) and `WBM_PEOPLE_HAIR_MOST` (hair meshes given strands in one frame, default 12). Off by default |
| `WBM_EYES` | Metal mode: `1` gives the eyes of faces a small sharp highlight from the sun and a faint reflection of the sky. The eyes are painted on the face texture at the same place for every face, which is where the effect is applied, in the engine's skin shader. The eyes also wander: held still for a second or two, then turned a little to one side or back to straight ahead, each face in its own time (`WBM_EYES_MOVE`, default 1, sets how far; `0` keeps them still). Shows in close-ups. Off by default |
| `WBM_SSS` | Metal mode: `1` gives skin subsurface scattering, done where it is lit: sunlight wraps a little way round the terminator, farthest in red; the red is lit from the smooth surface instead of the normal map's relief; and the edge of a shadow on skin is tinted red. It applies to whatever the engine draws with its skin shader (the faces of troops), and in the general shaders to draws whose texture's file name says face, body, hand or skin. In the general shaders torchlight and other point lights scatter the same way; the engine's skin shader keeps its own softer wrap for them. With `WBM_DYNAMIC_SHADOWS=1`, sunlight also comes through thin parts (ears, the wings of a nose) seen against the sun, within the shadow map's fine window, which measures how thick they are; `WBM_SSS_BACKLIGHT` (default 0.6, `0` for none) sets how strongly. Off by default |
| `WBM_MATERIALS` | Metal mode, with `WBM_PBR=2` or `3`: `1` sets metalness, roughness and highlight strength by what a texture shows (metal, cloth, leather, skin, wood, stone, horse) instead of estimating them from the specular mask alone. Textures are recognised by content against the files in the game's texture folders and classed by words in the file names; names that fit no class, or more than one, keep the estimate. Within those limits a surface counts as metal where the material is shiny and its colour is grey, and a metal loses most of its diffuse colour to reflection. Where a shader has a specular map, metalness is also read from it. `WBM_DEBUG_MATERIALS=1` shows the estimated metalness instead of the picture, white for metal and black for none. Off by default |
| `WBM_FXAA` | Metal mode: `1` smooths edges after the scene is drawn (FXAA), geometry and cut-outs such as leaves and hair alike, before the interface goes on top. A cheap stand-in for `WBM_MSAA`, and usable with it. Needs the game's HDR option. Off by default |
| `WBM_MAX_FPS` | Metal mode: a frame-rate limit, for example `60`; less work per second means a cooler, quieter machine. `WBM_MENU_FPS` is a separate limit for frames in which no 3D scene is drawn (menus, loading). No limits by default, beyond the game's own `max_framerate` |
| `WBM_MOTION_BLUR` | Metal mode: `1` blurs the scene along the camera's own movement, from each pixel's depth and the previous frame's camera. Nothing within a few metres of the camera is blurred by the camera's movement, so that the player's character stays sharp. Things that move by themselves (a sword swung, a horse's legs, a running man) are blurred by their own movement as well, however near: each object of the game's depth pre-pass is found again among last frame's and drawn with both poses into a half-size texture of screen movements, which the blur follows; that needs the game's depth effects, and takes one extra cheap draw for each moving object within 80 metres. `WBM_MOTION_BLUR_STRENGTH` (default 1) is the exposure time in units of 1/48 s. Needs the game's HDR option. Off by default |
| `WBM_LIGHT_SHAFTS` | Metal mode: `1` adds light shafts from the sun: bright sky near the sun is smeared along lines towards the sun's position on screen. Needs the game's HDR mode and a visible sun. `WBM_SHAFT_STRENGTH` (default 0.7) tunes it. Off by default |
| `WBM_TONEMAP` | Metal mode: `1` replaces the tone-mapping operator in the engine's final post-processing shader with one that leaves shadows and mid-tones as they are and rolls highlights off smoothly instead of clipping them. Needs the game's HDR mode. Off by default |
| `WBM_HDR` | Metal mode: `1` presents in extended range on displays that support it: highlights in the tone-mapped image are stretched above display white, up to the screen's current headroom or `WBM_HDR_PEAK` (default 4). Needs the game's HDR mode. Off by default |
| `WBM_TRILINEAR` | Metal mode: `1` blends every mipmapped texture between its two nearest mipmap levels. The game asks for most textures to switch levels abruptly (`GL_LINEAR_MIPMAP_NEAREST`), which shows as a line across the ground and walls a few metres ahead that moves with the camera. Off by default |
| `WBM_LOD_BIAS` | Metal mode: mip level bias for all textures, for example `-0.5` for sharper texturing. macOS 26 or later. Rendering at Retina resolution already selects sharper mip levels, so this is rarely needed |
| `WBM_AO` | Metal mode: `1` adds screen-space ambient occlusion to the scene before the engine's post-processing. Needs the game's HDR mode. `WBM_AO_RADIUS` (metres, default 0.6) and `WBM_AO_STRENGTH` (default 0.5) tune it; `WBM_AO_FULL=1` computes it at full instead of half resolution, which is sharper on fine detail and costs about four times as much. Off by default |
| `WBM_PBR` | Metal mode: `1` replaces the engine's Blinn-Phong highlights with microfacet ones (GGX, Smith shadowing, Schlick Fresnel), keeping each material's highlight strength and deriving roughness from its shininess. `2` also estimates metalness from the specular mask, darkens the base colour of metals and adds a reflection of a sky-and-ground environment built from the scene's light colours. `3` reflects the scene's actual sky instead: the engine's sky dome is redrawn each frame into a small six-face atlas that the shaders sample, blurred by roughness. Off by default: it changes how armour and weapons look |
| `WBM_SRGB` | Metal mode: `1` removes the shaders' own `pow(colour, 2.2)` on texture samples and binds sRGB views of the textures instead, for an exact decode before filtering. Off by default: it shifts dark tones slightly |
| `WBM_STATE_CACHE` | Metal mode: `0` issues every state-setting Metal call on every draw, as a baseline for measuring the saving. By default calls whose value is unchanged within a render pass are skipped |
| `WBM_SHADOWS` | Metal mode: `0` keeps the game's own 4-sample shadow filter. `1`, the default, filters over a 4x4 block of shadow-map texels for softer edges. `2` uses percentage-closer soft shadows: sharp where an object meets the ground, wider with distance from it |
| `WBM_CACHE` | Directory of the translated-shader cache. Default `~/Library/Caches/warband-metal`; `0` disables it |
| `WBM_DEBUG_CLEAR` | Metal mode: clears the screen to blue instead of the game's colour, to show that frames arrive |
| `WBM_CALLSITES` | Metal mode: `1` notes where in the game's own executable the rendering calls come from, and lists the paths in the run's `summary.txt`. For reading the engine: see `docs/engine-notes.md` |
| `WBM_OUT` | Output directory. `run.sh` sets it to `traces/<timestamp>`; otherwise `~/Library/Logs/warband-metal` |
| `WBM_TRACE_FRAMES` | Frames to log call by call and capture, for example `1-3,600` |
| `WBM_SNAP_EVERY` | Captures a frame to `frames/` every this many seconds, for example `10`. In trace mode each captured frame is also logged call by call |

A single frame can also be captured whole and looked at later without the game. While the game runs in Metal mode, `scripts/capture.sh [delay-seconds]` writes the next frame and everything it depends on to `capture_<n>.wbcap` in the run's output directory (several hundred MB). `make build/replay` builds a player for such files: `build/replay file.wbcap` shows the frame in a window, and `build/replay file.wbcap --png out.png` saves it as an image. The `WBM_*` variables apply to the player as they do to the game, so one captured frame can be compared across settings. Capture with the features of interest switched on: the player can turn them off, but cannot supply what the game was never asked for.

The same player shows single models from the game's files: `scripts/preview.sh sword_medieval_a` draws that mesh, with the game's own shader and textures for its material, in the newest captured frame in place of what the game drew there, so it is lit as in that scene and gets every feature of the renderer (`--keep-scene` leaves the scene in; `WBM_STAGE` names another capture). `scripts/preview.sh --list helmet` finds mesh names. In the window, `n` and `p` step through the meshes of the same resource file and `l` through a mesh's simpler versions. Skinned pieces are shown in their rest pose unless an action is played: for a horse, `a` steps through stand, walk, trot, canter, gallop, rear, jump and turn (`--anim gallop` starts with one, `--pose 0.5` holds it halfway, for stills), and `--anim animation:from:to:seconds` plays the named frames of any animation in the game's files, such as `--anim anim_horse:350:375:1` for a fall. Whole characters are not assembled.

Several models at once: `build/replay capture.wbcap --gallery file` places each line's model (`mesh material right up ahead turn`, in metres from the captured camera and degrees; see `scripts/showcase.txt` for the whole form) in the frame, and `@sphere` is a ball that wears any material, or one part of its texture (`full_plate[0.25,0.78,0.60,0.97]`). `scripts/showcase.sh` uses it for a material showcase: a ball for each kind of material the renderer treats differently (plate, mail, cloth, leather, skin, wood, stone, a horse's coat) and a row of real models (plate armour, a face, a helmet, a shield, a bush, a horse) in a castle hall lit by its torches. Run it with any setting changed to see what that setting does, for example `WBM_SSS=0 scripts/showcase.sh --png off.png`; `WBM_STAGE` puts it in another capture (an outdoor one for sunlight). The previewer reads the module named by `WBM_MODULE`, or else the one the game last played.

Denser forests, as data: `scripts/forest_flora.py "<module>"` writes the module's own `Data/flora_kinds.txt`, the game's list with forest-only copies of every tree (`--trees`, default twice their density again) and of the bushes and ferns that grow in forests (`--undergrowth`, default three times); `--remove` undoes it. Not into Native itself. Only scenes generated afterwards change. `scripts/flora_preview.py [--module "<module>"]` strews a square of ground in the previewer from such a list, to compare two lists without starting the game (a stand-in for the game's own scattering: `--region`, `--size`, `--seed`, `--rate`, `--png`; the gallery `@plane` and `_h` heights, which stand a model on the ground, are what it uses).

## Models and textures to Blender and back

The game's models can be taken out, worked on and put back. Nothing here touches the game's files unless `--install` is given.

    make build/gltf_export build/gltf_import build/texture_tool
    scripts/export-models.sh ~/models arabian        # models whose names contain a word (all of them without one)
    build/gltf_import ~/models/arabian_wall_a.glb -o ~/fixed --check
    build/gltf_import ~/models/town_house_c.glb -o ~/fixed --lods uv --install MyModule

- **Out**: `scripts/export-models.sh` writes one glTF file (`.glb`) per model, with its rig where it has one, and the textures once, into `textures/` beside them. `build/gltf_export <mesh>` does one, with `--anim` for an action.
- **Back**: `build/gltf_import` takes every mesh in the files that goes by the name of one of the game's and writes a copy of the resource file it lies in, with that mesh replaced and the rest as it was. Flags, materials and vertex colours stay the game's; tangents are worked out anew. `--check` says how each mesh compares with the game's, which for a file that has only been out and back should be: the same.
- **Into the game**: `--install <module>` copies those files into the module's `Resource` folder and changes the lines of its `module.ini` that load the game's own files of those names (`load_resource`) into ones that load the module's (`load_mod_resource`). What it replaces is kept beside it as `*.before`. Use a copy of a module, not Native itself.
- **To look first**: `scripts/preview-models.sh <folder or file.glb> <mesh>` takes the files into a stand-in for the game's folder under `build/` and shows the model from there; `--original` shows the game's own, and `--png out.png` writes stills of both from one camera.
- **Textures** come back through `build/texture_tool import` into a texture pack (see `WBM_TEXTURES` above); `scripts/preview-textures.sh <folder> <mesh>` shows a model wearing them.

- **From afar** the game shows a model by simpler meshes of its own (`name.lod1` and so on), which are not in a file from Blender. `--lods uv` carries a changed texture mapping over to them, each keeping its shape: every corner of a simpler mesh finds the spot of the full model it lies on and takes what that spot's mapping has become. Where the model's shape was changed too that cannot be done, and the full model takes their place (as it does throughout with `--lods copy`). Without the option they are left as they are, and a change shows up close only. `--check` says how far each was carried.

## How it works

`run.sh` starts the game binary with `DYLD_INSERT_LIBRARIES`. The game's OpenGL surface is 62 functions, listed in `src/gl_api.def`:

- 22 are imported from OpenGL.framework and replaced through a dyld interpose table, as are 7 SDL window and context functions.
- 40 are called through pointer variables exported by the game's bundled GLEW. The shim interposes `glewInit` and swaps those pointers after GLEW has filled them in.

In Metal mode the window is created without an OpenGL surface and gets a `CAMetalLayer`; the game receives a placeholder context, and the 62 functions are routed to `src/metal_backend.mm`, whose parts are in `src/backend/` by area (passes, textures, pipelines, ambient occlusion, motion blur, upscaling, shadows, strands, draws, the OpenGL calls).

Shaders are translated when a program is linked (`src/shader_xlate.cpp`), and the result is cached on disk (`src/shader_cache.cpp`), so later launches skip the translation. Metal then compiles the translated source in the background; a program waits for that only if it draws before its shaders are ready. The translation itself: the engine's GLSL 1.20 is rewritten to GLSL 4.50, compiled to SPIR-V by glslang and turned into Metal Shading Language by SPIRV-Cross. `make build/xlate_test && build/xlate_test traces/latest` runs that translation over every program a trace recorded and compiles the results with Metal.

The translation step can also change what a shader computes. The engine's shadow filter is recognised by its shape and replaced with a wider one (`soften_shadows` in `src/shader_xlate.cpp`). With multisampling on it also rewrites alpha tests into per-sample coverage (`smooth_alpha_tests`). Two more rewrites are optional: reversed depth (the clip-space mapping appended to every vertex shader) and hardware sRGB decoding (`decode_srgb_in_hardware`). `build/xlate_test traces/latest -s -a -z -g` checks that every program still compiles with all of them on.

Render-to-texture passes are drawn upside down, so that textures keep OpenGL's row order and the game's texture coordinates work unchanged.

AppKit also calls a few of the interposed functions when it presents the GL surface. Calls that do not come from the game binary are forwarded and counted separately.

Do not use the shim on multiplayer servers: it changes how the game process loads libraries.
